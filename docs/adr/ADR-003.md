> Esta decisión quedó sin efecto: el usuario eligió PostgreSQL el 25 de noviembre de 2026. Se conserva como registro histórico; la configuración vigente está en [ADR-006](ADR-006.md).

## Contexto

El documento del proyecto fija MySQL 8 como base de datos oficial. El repositorio había quedado configurado para PostgreSQL/Neon, lo que contradecía la restricción y hacía que el script `database/tienda_zapatos.sql` no se usara. Se necesita una configuración reproducible, sin claves en el repositorio y con pruebas que no dependan de un servidor externo.

## Decisión

1. La base oficial es MySQL 8 con `com.mysql:mysql-connector-j`.
2. El esquema se crea con `database/tienda_zapatos.sql`; la aplicación arranca con `spring.jpa.hibernate.ddl-auto=validate` para detectar desalineaciones entre entidades y tablas.
3. Las credenciales se leen de `DB_USER` y `DB_PASSWORD`, con valores por defecto `root` y vacío solo para desarrollo local.
4. Las pruebas usan H2 en memoria con `MODE=MySQL`, `DB_CLOSE_DELAY=-1` y `LOCK_TIMEOUT=10000`; nunca tocan la base real.
5. El dialecto de producción es `org.hibernate.dialect.MySQLDialect` y la zona horaria `America/Bogota`.

## Consecuencias positivas

- Se cumple la restricción de MySQL 8 y el script queda como fuente del esquema.
- `validate` evita que la aplicación arranque con tablas incompletas o columnas cambiadas.
- Las pruebas son rápidas, aisladas y no requieren MySQL instalado.
- No hay claves ni cadenas de conexión sensibles en el repositorio.

## Consecuencias negativas

- Antes del primer arranque hay que ejecutar el script; no se crea la base automáticamente.
- H2 en modo MySQL no reproduce todas las diferencias de MySQL (colaciones, tipos, bloqueos); la validación final requiere un MySQL real.
- `validate` puede fallar por diferencias menores de tipo o longitud si el script y las entidades se editan por separado.

## Alternativas consideradas

1. **`ddl-auto=update`.** Cómodo, pero puede alterar tablas sin revisión y ocultar errores de esquema. Se descarta para producción.
2. **PostgreSQL/Neon.** Era la configuración heredada, pero contradice la restricción. Se descarta.
3. **H2 también en producción.** No es MySQL y no cumple el requisito. Se descarta.
4. **Testcontainers con MySQL.** Más fiel, pero exige Docker y hace la suite más lenta; se prefirió H2 para el trabajo diario y se deja la verificación real como paso manual.

## Cumplimiento

- `pom.xml` declara `mysql-connector-j` en scope `runtime`.
- `src/main/resources/application.properties` apunta a MySQL 8 y usa variables de entorno.
- `src/test/resources/application.properties` usa H2 en modo MySQL.
- `README.md` documenta los pasos y las variables.
- `database/tienda_zapatos.sql` crea las tablas y restricciones.
