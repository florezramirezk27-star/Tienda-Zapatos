# ADR-006 — Cambiar la base oficial de MySQL 8 a PostgreSQL

| Campo | Valor |
|---|---|
| Estado | Aceptado por el usuario (desviación del DOCX) |
| Fecha | 25 de noviembre de 2026 |
| Decisores | Kevin Andréy Flórez Ramírez (usuario: cambio de base) |
| Requisitos afectados | NFR-ZAP-004 |
| Relacionado | ADR-003 (reemplazado), ADR-002 |

## Contexto

El DOCX `Tienda_de_Zapatos_Plan_de_Trabajo_Scrum_SDD.docx` fija MySQL 8 como base oficial: NFR-ZAP-004 exige «guardar todos sus datos en MySQL mediante JPA y no usar MongoDB», y la constitución y el plan replican esa restricción. El equipo migró la configuración a MySQL, pero en este entorno no hay MySQL 8: el servicio local disponible es PostgreSQL en `localhost:5432`. Por eso el usuario decidió usar PostgreSQL; la validación real contra ese servidor ya se ejecutó y se documenta al final de este ADR.

Al consultar al usuario, eligió expresamente **cambiar a PostgreSQL** para usar el servicio local. Esta decisión contradice el documento fuente, por lo que debe quedar registrada como desviación y no como cumplimiento de NFR-ZAP-004.

## Decisión

1. La base oficial es PostgreSQL. Hay **dos entornos con el mismo esquema**: PostgreSQL local para desarrollo/STS y Neon para Render (producción). No son dos bases compitiendo.
2. `pom.xml` usa `org.postgresql:postgresql` en scope `runtime` en lugar de `com.mysql:mysql-connector-j`.
3. `src/main/resources/application.properties` toma la URL de `DB_URL` y usa por defecto `jdbc:postgresql://localhost:5432/tienda_zapatos`; conserva `org.postgresql.Driver`, `PostgreSQLDialect` y `ddl-auto=validate`.
4. `database/tienda_zapatos.sql` es el esquema local y `database/tienda_zapatos_neon.sql` es el mismo esquema adaptado a Neon (`public`, `sslmode=require` en la URL de Render). Ambos se mantienen.
5. Las credenciales siguen leyéndose de `DB_URL` / `DB_USER` / `DB_PASSWORD`; la clave nunca se guarda en el repositorio ni se escribe en logs (NFR-ZAP-005).
6. `TIENDA_DATOS_DEMO` controla los datos ficticios: `true` en local, `false` en Render.
7. Las pruebas automáticas usan H2 en memoria con `MODE=PostgreSQL` y `LOCK_TIMEOUT=10000`; siguen sin tocar ninguna base real.

## Entornos

| Entorno | Base | Configuración | Script |
|---|---|---|---|
| Local / STS | PostgreSQL en `localhost:5432`, base `tienda_zapatos` | `DB_URL` no definido; `DB_USER` y `DB_PASSWORD` en la Run Configuration | `database/tienda_zapatos.sql` |
| Render | Neon (PostgreSQL en la nube) | `DB_URL`, `DB_USER`, `DB_PASSWORD` y `TIENDA_DATOS_DEMO=false` en Environment | `database/tienda_zapatos_neon.sql` |
| Pruebas | H2 en memoria, modo PostgreSQL | `src/test/resources/application.properties` | `ddl-auto=create-drop` |

El mismo JAR sirve para ambos entornos: Render define `DB_URL`; local no la define y cae al valor por defecto.

## Consecuencias positivas

- La validación de `ddl-auto=validate` puede ejecutarse contra el PostgreSQL local existente.
- El esquema versionado vuelve a ser la fuente única de la estructura de tablas.
- No hay claves en el repositorio; la configuración sigue siendo reproducible por variables de entorno.

## Consecuencias negativas

- **NFR-ZAP-004 ya no se cumple según su redacción original** (`docs/trazabilidad.md` lo marca como desviación, no como «Verde»). La constitución, el plan y el README también quedan desviados del DOCX.
- H2 en modo PostgreSQL no reproduce todas las particularidades del servidor real (bloqueos, tipos, secuencias); la verificación definitiva sigue siendo el arranque contra PostgreSQL.
- Si el docente/PO exige el DOCX literal, hay que revertir esta decisión y restaurar ADR-003.

## Alternativas consideradas

1. **Mantener MySQL 8 e instalarlo con Docker.** Cumpliría el DOCX; el usuario lo descartó al elegir PostgreSQL.
2. **Un solo entorno (solo local o solo Neon).** Rechazado: el usuario usa PostgreSQL local en STS y Neon en Render; la solución debe soportar ambos con el mismo código.
3. **H2 en producción.** Rechazado: no es una base de datos oficial ni permite validar el esquema real.

## Cumplimiento / evidencia

- `pom.xml`: dependencia `org.postgresql:postgresql`.
- `src/main/resources/application.properties`: `DB_URL` con valor por defecto local, driver y dialecto PostgreSQL, `TIENDA_DATOS_DEMO`.
- `src/test/resources/application.properties`: H2 en modo PostgreSQL.
- `database/tienda_zapatos.sql`: esquema local compatible con `validate`.
- `database/tienda_zapatos_neon.sql`: esquema para Neon usado por Render.
- `docs/trazabilidad.md`: NFR-ZAP-004 en estado «Desviación autorizada (ADR-006)».
- Verificación real: esquema aplicado y arranque con `spring.jpa.hibernate.ddl-auto=validate` correcto contra PostgreSQL 16.15 el 25 nov 2026; 82/82 pruebas en verde con H2 modo PostgreSQL.
