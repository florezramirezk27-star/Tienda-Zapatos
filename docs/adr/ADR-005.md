# ADR-005 — PDF aislado en el paquete `pdf`

| Campo | Valor |
|---|---|
| Estado | Aceptado |
| Fecha | 13 de noviembre de 2026 |
| Decisores | Kevin Andréy Flórez Ramírez y Juan Miguel Corales |
| Requisitos | REQ-ZAP-033 a REQ-ZAP-038, NFR-ZAP-006 |
| Relacionado | ADR-002 |

## Contexto

La tienda debe generar facturas y reportes de ventas en PDF. La API de PDF es una dependencia externa que puede cambiar de versión o fallar en tiempo de ejecución. Si los controladores o las plantillas conocen sus clases, cualquier cambio obliga a tocar varios puntos y el fallo se propaga sin un mensaje claro.

## Decisión

1. Todo el uso de OpenPDF se concentra en `com.tiendazapatos.pdf`.
2. `GeneradorPdf` expone dos operaciones: `factura(Pedido)` y `reporte(ResumenVentas)`; devuelve `byte[]`.
3. Los controladores solo llaman a `GeneradorPdf` y construyen la respuesta HTTP con `Content-Type: application/pdf` y `Content-Disposition`.
4. Si la API falla, `GeneradorPdf` lanza `PdfGeneracionException`; el controlador la convierte en un mensaje para el usuario y el pedido no se modifica.
5. Las pruebas extraen el texto del PDF con `PdfTextExtractor` para verificar número, ítems, IVA, total y mensajes, no solo la cabecera `%PDF`.

## Consecuencias positivas

- Un cambio de API o de versión se resuelve en un solo paquete.
- Los controladores quedan delgados y testeables con un mock de `GeneradorPdf`.
- El fallback se prueba de forma determinista con `@MockitoBean`.
- El contenido del PDF se verifica de verdad, no solo el tipo MIME.

## Consecuencias negativas

- `GeneradorPdf` concentra maquetación y puede crecer; se mantiene con métodos privados por sección.
- El PDF no es accesible para lectores de pantalla como el HTML; es un comprobante descargable.
- La extracción de texto depende del orden de las celdas y puede requerir ajustes si cambia la maquetación.

## Alternativas consideradas

1. **Generar HTML y imprimir a PDF con el navegador.** No produce un archivo verificable desde el servidor y depende del usuario. Se descarta.
2. **Usar la API directamente en los controladores.** Acopla la capa web a OpenPDF y dificulta el fallback. Se descarta.
3. **iText 7.** Licencia AGPL/comercial; OpenPDF es LGPL/MPL y suficiente. Se elige OpenPDF.

## Cumplimiento

- `GeneradorPdf` y `PdfGeneracionException` son las únicas clases que importan `com.lowagie.text`.
- `FacturaController` y `ReporteController` capturan `PdfGeneracionException`.
- `FacturaPdfFallbackTest` prueba AC-035.1 con un mock que falla.
- `TiendaIntegracionTest` extrae texto de factura y reporte para AC-033.1, AC-036.1 y AC-038.1.
